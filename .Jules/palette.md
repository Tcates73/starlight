## 2024-02-14 - Dynamic Text Accessibility
**Learning:** Adding `aria-live="polite"` to dynamically updated text nodes that convey important feedback (e.g., scores, status texts in dashboards) ensures proper screen reader accessibility. Progress bars should also have `role="progressbar"`, `aria-valuemin`, `aria-valuemax`, and dynamic `aria-valuenow`.
**Action:** Always verify if text nodes updated via JavaScript convey status or feedback, and apply `aria-live="polite"` to them. Apply appropriate ARIA progressbar roles to custom visual meters.## 2024-06-13 - Form Accessibility and Focus States
**Learning:** Explicitly linking labels and inputs with `for` and `id` attributes improves the click area for users and context for screen readers. Using `:focus-visible` with `outline-offset` provides clear visual feedback for keyboard navigation without affecting mouse users. Appending a visual required indicator (e.g., an asterisk) hidden from screen readers (`aria-hidden="true"`) clarifies necessary fields without cluttering auditory feedback.
**Action:** Always verify form fields have explicit `id`/`for` links, custom focus rings (`:focus-visible`), and visual required indicators that are accessible.
